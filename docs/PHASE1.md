## Implementation sequence

1. Shared deterministic 150 × 150 metre map definition, circulation and park footprint.
2. Independent Rapier world, static collision proxies and capsule FPS movement.
3. Town facades, windows, awnings, trees, planting, benches, lighting, playground,
   terrace, stairs, walls, fences, bollards, bins and fountain.
4. Three.js instancing, daylight, shadows, atmosphere, F1/F2/F3 and diagnostics.
5. Physics tests, browser screenshots, mode parity tests and production build.

## Boundaries

- `world/types.ts`, `random.ts`, `generate.ts`: seed/version/units/object IDs,
  spawn and stable transforms. Pure data; independent of SOLO/VERSUS.
- `render/world.ts`: disposable instanced meshes and terrain; a separate invisible
  BVH ground query mesh remains usable in F2. `groundAt(x,z)` is a real BVH query.
- `physics/world.ts`: independent Rapier colliders and kinematic capsule controller.
  Rendering visibility never changes colliders. Terrain visual mesh and trimesh
  collider share vertices. Organic rocks use conservative cuboid proxies.
- `player/input.ts`: keyboard, pointer lock / drag fallback, mobile two-side drag,
  blur/visibility input reset. Radius 0.3m, capsule height 1.6m, eye height 1.65m.
- `main.ts`: mode orchestration and fixed 60Hz physics (maximum 6 catch-up steps).
- `diagnostics/performance.ts`: FPS, CPU frame duration, max CPU time, draw calls,
  triangles, geometries and textures. GPU timing/memory is not claimed.

No audio/sonar engine, networking, combat, story or authoritative server is added.
Future sonar should consume stable object IDs/transforms and query meshes, and
provide a separate rendering pass. No game rule needs to modify the background.
The same definition can be generated by either game mode; multiplayer determinism
of Rapier across devices is not promised by this phase.

Three 0.186.1 satisfies both terrain and BVH upstream peer ranges. No runtime
THREE.Terrain dependency is installed. BVH has no additional runtime dependency
besides Three. Rapier compat embeds WASM and has no Three peer dependency.
Vite 7.3.1 requires Node 20.19+ or 22.12+; verified on Node 24.19.
`@types/three` 0.185.0 is the available close type baseline; strict build passes
against runtime 0.186.1. `public/THIRD_PARTY_NOTICES.txt` plus full license files
are copied by Vite into the production distribution. Credits are accessible in HUD.

## Performance and limitations

Repeated shapes are InstancedMesh buckets sharing primitive geometries/materials.
Tree crowns have 10 × 7 sphere segments; grass is low-poly, unshadowed geometry.
One 2048² directional shadow map, capped device pixel ratio 1.75, no postprocessing
or dynamic local lights. Decorative flowers and crowns do not block walking;
trunks, buildings, bench seats/backs, fences, stairs and cover have proxies.
Buildings are exterior volumes without traversable interiors; no slopes beyond
planted mounds, no jumping. The fountain is a still-water basin, no particles.

CPU timing measures update + render submission; GPU time requires device profiling.
Rapier's embedded WASM causes a ~2.24MB minified physics chunk (~830KB gzip).
Vite reports a chunk-size advisory; it is not a build error.
Real iPad/iPhone/Windows GPU performance and touch feel require device playtesting.
