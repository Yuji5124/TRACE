# Phase 3B — 方向を持つ ECHO HUNTER

基準main: `9a5176b`。Phase 3Aの敵1体を維持し、視野角と振り向き時間を追加。
テストプレイ: https://yuji5124.github.io/TRACE/

## 今回の遊び方と調整値

F2でQを出し、浮かび上がった敵の顔の突起から向きを読む。音を聞いた敵が振り向く間に移動する。
背後も近すぎれば足音が届くため、歩行4m・走行8mを考えて距離を取る。壁で視線を切って逃げる。
従来の音量OFF時の近接注意文・捕捉時の画面演出・5秒の再捕捉防止を維持。

| 項目 | 値 |
|---|---|
| IDLE / RETURN | 水平視野90度、視認距離6m |
| INVESTIGATE / SEARCH / CHASE | 水平視野110度、視認距離13m |
| 向きの変化上限 | 通常2.4rad/s（約138度/秒）、CHASE 3.2rad/s（約183度/秒） |
| 視線の遮蔽 | 従来のRapier raycast、視野内でも壁越しに視認しない |
| 見失い | 0.8秒後、最後の視認地点をSEARCH。現在位置を目標にし続けない |
| 接触 | 1.05m未満・遮蔽なしなら背後でも捕捉。接触による捕捉と視覚による追跡は別判定 |

設定は `src/hunter/config.ts`。水平角に加えて3次元距離で制限する。垂直視野角・認識時間の蓄積は未実装。
範囲内・視野内・遮蔽なしの条件が成立した次の10Hz判断で認識する。視野の縁に認識の遅延はない。

音を聞いた直後の停止中は記憶した音源へ、その後は経路の次の点へ最短角で徐々に向く。
SEARCH中に進路がない場合は向きを変えて探索する。無音の背後のプレイヤーへ直接振り向かない。
リセット時の向きは+Zへ戻す。通常モデルと音波モデルに同じ非発光の顔の突起を追加し、頭と知覚方向を一致させた。
F2で敵や方向のマーカーを常時表示しない。

F3限定で視野コーン、角度・距離・向き・判定理由（outside-cone / occluded / out-of-range / visible）を表示。
コーンはデバッグ専用のLineで、音波の参照メッシュに含めない。Geometryのバッファを再利用し、破棄にも対応。
実際の視認はコーン形状の描画ではなく、角度計算とRapier視線で判定する。

## 性能と制限

Linux headless Chromium 153 / SwiftShader、900×600。実GPUの計測ではない。
固定ステップ10秒分（描画なし）の実行79.3ms、AI判断100回、経路探索6回、試験全体のAI最大1.6ms。
起動時のナビ格子生成372.7ms。F2でQを0.8秒ごとに出す3.5秒の短いRAF試験は約3FPS、97 calls / 122044 triangles。
GPU timer値248.0msもSwiftShaderの参考値。CPU frameMs 2.80msは画面のFPSや実GPU性能を示す値ではない。
負荷が小さいと断定できず、Windows Chromeの実GPUでの追跡中・多数音波中の計測を次に行う。

実際に観察した点: 背後の歩行は通過できたが、同じ場所の走行は敵を振り向かせた。Qで呼ぶと調査後に追跡へ移り、走ると追加のRUN音が出た。
予想外に、経路の角では移動方向へすぐ体が揃わず、横向きに歩く短い区間ができる。振り向きの上限を優先した結果で、次の実機試遊で違和感を評価する。
